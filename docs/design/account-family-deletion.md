# 逻辑账号组删除设计

## 理解摘要

- 管理员需要从“逻辑账号”列表删除一个完整账号组。
- 删除前必须二次确认，避免误删不可恢复的本地凭据。
- 删除操作以逻辑账号组为边界，同时移除组内 Build、Web、Console 成员。
- 成员的额度、模型能力、账号关联等子数据必须随成员一起清理。
- 删除必须原子执行，任何数据库错误都应使整组数据回滚。
- 代理资源本身不删除，只因账号组消失而解除绑定。
- 不调用上游注销接口，不提供软删除或恢复站。

## 假设与非功能要求

- 每个逻辑账号组仅包含少量 Provider 成员，按组同步删除即可满足性能要求。
- 接口沿用管理端路由组的现有鉴权和错误响应规范。
- 删除后由前端失效逻辑账号、Provider 账号和代理列表缓存。
- 运行态账号粘性会话和凭据刷新状态按成员标识尽力清理；数据库事务失败时不报告成功。
- 历史审计记录和已生成媒体资产按现有保留策略继续保存；账号关联的媒体任务记录和上传票据随账号组删除。

## 方案比较

### 方案一：服务层编排、仓储单事务删除（采用）

服务层根据逻辑账号组删除结果清理运行态，仓储在一个事务中查询成员标识、删除全部成员并删除账号组。该方案能显式处理不存在、事务回滚和运行态清理，职责边界清晰。

### 方案二：前端逐个调用账号删除接口

复用现有单账号接口，但多个请求可能部分成功，无法保证原子性，且前端需要了解组内成员细节，因此不采用。

### 方案三：仅依赖数据库外键级联

删除账号组后由数据库级联成员。实现代码少，但现有模型未以账号组删除作为级联根，且服务层无法可靠获得成员标识清理运行态，因此不采用。

## 最终设计

1. 在账号仓储接口增加 `DeleteFamily`，返回已删除的成员标识。
2. 关系型仓储在单个事务中锁定或查询账号组及成员；账号组不存在返回统一的未找到错误。
3. 事务内先删除成员关联的媒体上传票据和任务记录，再删除组内全部 Provider 账号并沿用现有账号子表级联规则，最后删除空账号组；已生成媒体资产保留。
4. 应用服务调用仓储完成持久化删除；成功后按成员标识清理粘性会话和刷新状态。
5. HTTP 层新增 `DELETE /account-families/:id`，成功返回删除成员数。
6. 前端新增删除请求、行级删除按钮和危险操作确认框；成功后刷新逻辑账号、三个 Provider 账号及代理缓存。
7. 仓储测试覆盖三类成员、子数据、媒体任务和上传票据删除，以及代理、媒体资产保留和不存在；HTTP 测试覆盖成功与不存在响应；前端通过类型检查和构建验证。

## 风险

- 删除不可恢复：通过明确的二次确认文案降低误操作风险。
- 子表外键差异：通过关系型仓储集成测试验证当前 SQLite 测试数据库上的真实级联结果。
- 媒体任务使用限制删除外键：在账号事务中显式删除任务和上传票据，同时保留已生成媒体资产。
- 运行态与数据库并非同一事务：仅在数据库成功后清理运行态；运行态清理失败沿用现有尽力而为策略，过期状态不会恢复已删除账号。

## 决策记录

- 决定由服务层发起、仓储单事务按 `family_id` 删除；替代方案是前端逐项删除或纯外键级联，选择原因是原子性和清晰的层次边界。
- 决定返回删除的成员标识；替代方案是删除前由服务层逐项读取，选择原因是避免事务外数据竞争并支持运行态清理。
- 决定保留代理与历史审计；替代方案是扩大级联范围，选择原因是代理属于可复用资源，历史审计遵循现有数据保留策略。
- 决定只提供单组删除；替代方案是同步加入批量删除，选择原因是当前需求仅要求行级删除，遵循最小实现范围。

## 验收标准

- [x] “逻辑账号”列表每行提供删除入口和二次确认。
- [x] 删除一个逻辑账号组会原子删除其全部 Build、Web、Console 成员。
- [x] 成员额度、模型能力、账号绑定、媒体任务和上传票据等关联数据被清理，已生成媒体资产保留。
- [x] 绑定代理资源保留，其他逻辑账号组不受影响。
- [x] 不存在的逻辑账号组返回未找到，失败时不出现部分删除。
- [x] 删除成功后相关前端列表缓存被刷新并显示成功提示。
- [x] 后端测试、前端类型检查、构建和代码检查通过。
