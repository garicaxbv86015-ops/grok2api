# 逻辑账号组统一代理设计

## 目标理解

- 一个上游登录身份定义为一个“逻辑账号组”。
- Grok Web、Grok Build、Grok Console 是同一逻辑账号组下的三条 Provider 凭据。
- 新增顶级“IP 管理”菜单，集中维护可复用的代理资源。
- 每个逻辑账号组最多绑定一个代理，三种 Provider 的所有上游请求共用该代理。
- 已绑定代理不可用时严格失败，不允许切换其他代理或直连。
- 未绑定代理的逻辑账号组继续使用现有按 Provider 作用域划分的出口节点池。
- 首版支持代理增删改查、搜索筛选、分页、单条连接测试、绑定账号数量，以及独立逻辑账号列表中的单条和当前页批量代理绑定。

## 假设与非目标

- 首版通用代理支持 HTTP、HTTPS、SOCKS5、SOCKS5H。
- 代理地址和认证信息加密保存，管理 API 不回显敏感值。
- 被逻辑账号组引用的代理禁止删除，管理员需先解除绑定。
- 首版不实现代理自动分配、备用代理、代理导入导出、批量质量检测、跨页选择和地理位置识别。
- 现有出口节点和运行时设置保持兼容，不迁移或删除现有节点。

## 方案比较

### 方案一：三条 Provider 账号分别保存代理

实现量较小，但同一登录身份的三条记录可能发生代理漂移；Console 当前又没有正式的 Web 关联外键，后续维护成本高。

### 方案二：逻辑账号组统一保存代理

新增逻辑账号组实体，三条 Provider 凭据引用同一组，代理只在组上保存一次。该方案能够从数据约束上保证代理一致，是本次采用的方案。

### 方案三：仅使用代理 URL 中的账号占位符

不增加管理模型，但只能适配支持租约模板的特定代理服务，不能满足通用代理的显式维护与绑定需求。

## 最终设计

### 数据模型

- `proxies`：通用代理资源，保存名称、加密代理 URL、启用状态、最近测试结果和时间戳。
- `account_families`：逻辑账号组，保存可空的 `proxy_id` 和时间戳。
- `provider_accounts.family_id`：Provider 凭据所属逻辑账号组，建立索引和外键。
- Web 导入创建逻辑账号组；Web 转换 Build、同步 Console 时继承相同的 `family_id`。

### 出口规则

1. Provider 请求读取凭据所属逻辑账号组的代理快照。
2. 逻辑账号组已绑定代理时，按 Provider 构建相应传输客户端，但代理 URL 保持一致。
3. 绑定代理禁用、缺失或连接失败时返回错误，不进入现有出口池。
4. 逻辑账号组未绑定代理时，继续执行现有作用域出口节点选择逻辑。

### 管理接口与页面

- `/api/admin/v1/proxies`：列表、创建、更新、删除。
- `/api/admin/v1/proxies/:id/test`：单条代理连接测试。
- `/api/admin/v1/account-families`：按成员名称、邮箱分页搜索逻辑账号组，并返回 Web、Build、Console 成员摘要。
- `/api/admin/v1/account-families/:id/proxy`：绑定、切换或解除整个逻辑账号组的固定代理。
- `/api/admin/v1/account-families/batch/proxy`：在单次事务内为当前页手动勾选的账号组统一绑定、切换或解除代理。
- 账号更新接口仍兼容组级代理绑定，并在账号响应中返回代理 ID 与名称。
- 逻辑账号查询支持按成员信息或代理名称模糊匹配，并支持全部、已绑定、未绑定三种绑定状态筛选。
- 前端新增 `/proxies` 页面和“IP 管理”菜单；账号页面增加“逻辑账号”页签，每行直接展示三类成员和代理绑定入口，并支持当前页勾选和全选。

### SQLite 升级保护

- SQLite 的表结构升级可能通过删除、重命名父表完成，父表删除会触发子表的 `ON DELETE CASCADE`。
- 所有结构自动迁移固定在同一物理连接，迁移期间暂停外键执行，迁移结束后执行 `foreign_key_check` 并恢复外键。
- 升级回归测试以旧版 `provider_accounts` 结构为输入，校验凭据、Provider 关联、Web 配置、额度和 Billing 行数及内容完全保留。

## 决策日志

- 决定引入逻辑账号组，而不是在三条 Provider 账号上复制代理字段；原因是需要数据库级一致性。
- 决定代理作为独立通用资源，不直接复用带 Provider 作用域的出口节点；原因是账号代理需要跨 Build、Web、Console 共享。
- 决定严格固定已绑定代理；原因是自动换 IP 会破坏账号出口一致性。
- 决定保留现有出口节点池作为未绑定账号的默认路由；原因是保证现有部署无破坏升级。
- 决定在账号页面增加独立“逻辑账号”列表；原因是代理绑定对象是账号组，不能要求管理员从任意一条 Provider 凭据间接操作。
- 决定批量绑定仅作用于当前页手动勾选项，翻页或改变查询条件时清空选择；原因是操作范围必须清晰可见。
- 决定批量绑定使用独立事务接口，而不是前端循环调用单条接口；原因是必须保证全部成功或全部回滚。
- 决定复用逻辑账号搜索框模糊匹配代理名称，并增加独立绑定状态筛选；原因是两种查询方式互补且不会增加额外页面层级。
- 决定首版不包含批量质量检测、地理位置和导入导出；原因是它们不影响核心绑定闭环。

## 验收标准

- 同一逻辑账号组的 Web、Build、Console 请求审计显示相同代理资源。
- 转换和同步产生的 Provider 凭据自动加入原逻辑账号组。
- 更新一次逻辑账号组代理后，三种 Provider 无需分别修改即可生效。
- 管理员可在“逻辑账号”列表中查看每组 Web、Build、Console 成员，并完成绑定、切换、解绑。
- 管理员可勾选当前页任意账号组统一绑定、切换或解绑；任一目标无效时不得产生部分更新。
- 管理员可按代理名称模糊搜索，并筛选已绑定或未绑定的逻辑账号组。
- 已绑定代理不可用时请求失败且不发生直连或代理池回退。
- 删除被引用代理返回明确冲突错误。
- 代理密码、完整认证 URL 不通过列表或详情 API 回显。
- 从旧版 SQLite 数据库升级后，所有账号子表行数、凭据内容及关联关系保持不变。
